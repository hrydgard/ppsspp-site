# AGENTS.md

Notes for AI agents (and humans) working on the ppsspp.org site. Keep this updated as you learn things.

## Overview

- Static site for the PPSSPP PSP emulator, generated by a small custom Rust generator (`src/`), templated with Handlebars (`template/*.hbs`, pinned to `handlebars = "=6.4.0"`).
- Don't upgrade the `markdown` crate past what `Cargo.toml` says (there's a warning comment there).
- `cargo run` builds into `build/` and serves on `localhost:3000`, rebuilding on changes to `data docs news pages static template`. `cargo run -- --skip-serve` just builds.
- `build/` is not cleaned by `cargo run`, so stale output from removed/renamed posts (and `page/N` folders past the current last page) stays around locally. `deploy.sh` does `rm -rf build` first, then rsyncs with `--delete-after` to `/srv/www/ppsspp.org/{dev,prod}`.
- The backend (`/api`, accounts, purchases) is closed source. Client-side login state lives in `static/script/account.js`.
- `drafts/` is never published.

## Content layout

- `docs/` → `gen_doctree.rs`, `pages/` (`.hbs` / `.md`) → `gen_pages.rs`.
- `news/` → `gen_blog::generate_blog(config, "news", "News", …)` in `src/main.rs` `build()`. This is the site's only post feed. A separate `blog/` folder was merged into it on 2026-09-25, and nginx 301-redirects `/blog/*` to `/news/*` (see below).
  - Type tags: `releases` (changelogs), `news` (announcements, store/platform news), `blog` (long-form articles; former blog posts). Topic tags like `rendering-tricks` can be added on top of these.
  - The 3 newest posts feed `globals.latest_news` on the front page.
  - Before the merge, major releases got a pair of posts: a changelog (`release-X.Y`) and a narrative post (`X-Y-release-announcement`). The old pairs stay as they are, but new releases get a single post.
  - Images for posts live under `static/img/blog/...` (the path is historical; leave it).
- Post filenames are `YYYY-MM-DD-name.md`; the date comes from the filename. Front matter: `slug`, `title`, `authors`, `tags: [a, b]` (parsed in `document.rs`). Missing slug → falls back to the filename remainder with a warning.
- URL of a post: `/{folder}/{slug}`. Other outputs per folder:
  - Listing, paginated: `/news`, `/news/page/N`. Tag listings are paginated the same way: `/news/tags/{tag}`, `/news/tags/{tag}/page/N`. Page size is `POSTS_PER_PAGE` at the top of `src/gen_blog.rs` (currently 5). Pages count from the newest post, so page URLs shift whenever a post is added.
  - `/news/archive`: every post title grouped by year (`template/blog_archive.hbs`).
  - `rss.xml` and `atom.xml`: all posts, not paginated.
- Sidebar: shows the newest `SIDEBAR_RECENT_POSTS` (20), plus the current post if it's older than those, plus an "All posts" link to the archive.
- Excerpts: a line containing only `<!-- more -->` (or `<!--more-->`), with blank lines around it, makes listings show only the part above it, followed by a "Read more" link. The split happens on the rendered HTML, so the marker must be its own block, not inside a paragraph or list. The post page and the feeds are unaffected.
- `PageContext.pagination` drives the pager in `blog_page.hbs` and the `<link rel=prev/next>` tags in `common_header.hbs`. Listing and archive pages use a synthetic `DocumentMeta` (url + section), so the top nav gets highlighted and `meta.section` works in templates.

## Performance

- A full build takes ~1 s in dev (`cargo run`), ~9.6 s before the fixes below. To find hot spots, timestamp each output line (`... | while read l; do echo "$(date +%s%N) $l"; done`), or wrap calls with an `Instant`-based accumulator. `perf` isn't installed.
- Handlebars serializes the whole render context to JSON on **every** render, and `PageContext` includes `globals`. Keep `GlobalMeta` small: bulky data (downloads, platforms, screenshots, ~180 KB of JSON) lives in `PageData` (`globals.page_data`, `#[serde(skip)]`), which is exposed as `page_data.*` only to `pages/*.hbs` (set in `Document::from_hbs`). Before this split, rendering took 6.9 of the 9.6 s.
- `[profile.dev.package."*"] opt-level = 2` in `Cargo.toml` optimizes dependencies (markdown, handlebars) in dev builds. That cut ~2.3 s to ~1 s, at the cost of a one-time ~70 s compile of dependencies.
- The ad hoc servers JSON is fetched from GitHub once per process, not on every watch-mode rebuild (it happens in `run()`, not `build()`).
- Markdown is parsed 2–3 times per document (summary extraction in `post_process.rs`, rendering, and the search index for docs). That's cheap (<1 s in debug before deps were optimized), so it wasn't worth merging.
- The output is deterministic (posts from the same day are sorted by slug; the search index is a `BTreeMap`), so to check that a refactor doesn't change output, build before/after and `diff -r` (ignore `lastBuildDate`/`<updated>` in the feeds). Build the "before" state in a `git worktree` with a separate `CARGO_TARGET_DIR`.
- A running `cargo run` dev server keeps its old binary but rebuilds on template changes, so after changing Rust code that templates depend on, it must be restarted. It also writes into the same `build/` dir, which can mess up before/after comparisons.

## Gotchas found so far

- `feed.rs` hardcodes `https://www.ppsspp.org/{folder}` in feed links.
- `gen_sitemap.rs` collects entries but actually writing `sitemap.xml` is commented out.
- `main.rs` top-of-file checklist tracks planned work ("Merge the two blogs", "Blog feed pagination", …).
- No headless browser is installed locally, so visual checks have to be done by the user.

## Server (nginx)

- Host `www@main` (ssh works; no sudo). Config: `/etc/nginx/sites-available/default`, nginx 1.18. `www.ppsspp.org` serves `/srv/www/ppsspp.org/prod/build`, `dev.ppsspp.org` serves `.../dev/build`. Each server block ends with a list of `location = /old { return 301 /new; }` redirects.
- nginx listens on :80 behind Cloudflare, so relative `return 301 /x` produces `Location: http://...` (an extra hop). Use `https://$host/...` in new redirects.
- To test a config change without root, run nginx with a throwaway config in a temp dir: `nginx -t -p $d -c $d/t.conf`, or even start it on a high port and `curl -H "Host: www.ppsspp.org"`. The "could not open error log" alert is harmless.
