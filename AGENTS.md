# AGENTS.md

Notes for AI agents (and humans) working on the ppsspp.org site. Keep this updated as you learn things.

## Overview

- Static site for the PPSSPP PSP emulator, generated by a small custom Rust generator (`src/`), templated with Handlebars (`template/*.hbs`, pinned to `handlebars = "=6.4.0"`).
- Don't upgrade the `markdown` crate past what `Cargo.toml` says (there's a warning comment there).
- `cargo run` builds into `build/` and serves on `localhost:3000`, rebuilding on changes to `data docs news pages static template`. `cargo run -- --skip-serve` just builds.
- `build/` is not cleaned by `cargo run`, so stale output from removed/renamed posts (and `page/N` folders past the current last page) stays around locally. `deploy.sh` does `rm -rf build` first, then rsyncs with `--delete-after` to `/srv/www/ppsspp.org/{dev,prod}`.
- The backend (`/api`, accounts, purchases) is closed source. Client-side login state lives in `static/script/account.js`.
- `drafts/` is never published.
- Line endings: `.gitattributes` has `* text=auto eol=lf`, so text files are LF in the repo and in every checkout (normalized 2026-11-18).
- The app links to some pages directly (`UI/MainScreen.cpp` in the ppsspp repo): `/getgames`, `/getgames_ios`, `/gethomebrew(_ios)`, `/buygold(_ios)`, `/download`, `/privacy`, and `/getgames.html` from the disc-swap screen. `getgames` and `getgames_ios` are the most common landing pages. Don't rename them, and keep them short and current.

## Content layout

- `docs/` → `gen_doctree.rs`, `pages/` (`.hbs` / `.md`) → `gen_pages.rs`.
- `news/` → `gen_blog::generate_blog(config, "news", "News", …)` in `src/main.rs` `build()`. This is the site's only post feed. A separate `blog/` folder was merged into it on 2026-09-25, and nginx 301-redirects `/blog/*` to `/news/*` (see below).
  - Type tags: `releases` (changelogs), `news` (announcements, store/platform news), `blog` (long-form articles; former blog posts). Topic tags like `rendering-tricks` can be added on top of these.
  - The 3 newest posts feed `globals.latest_news` on the front page.
  - Release posts (`release-X.Y`, tag `releases`) have the narrative first, then a `<!-- more -->` marker, then `## Detailed changelog` (link to it with `#detailed-changelog`) with `### What's new in X.Y.Z` sections, newest first.
  - 1.15–1.20.4 used to have a pair of posts each: a changelog (`release-X.Y`) and a narrative post (`X-Y-release-announcement`, or `progress-report-spring-2023` for 1.15). On 2026-09-30 each pair was merged into the `release-X.Y` post, and nginx redirects the old narrative URLs. `1-15-release-process` is a separate post, not part of a pair.
  - Images for posts live under `static/img/blog/...` (the path is historical; leave it).
- Post filenames are `YYYY-MM-DD-name.md`; the date comes from the filename. Front matter: `slug`, `title`, `authors`, `tags: [a, b]` (parsed in `document.rs`). Missing slug → falls back to the filename remainder with a warning.
- URL of a post: `/{folder}/{slug}`. Other outputs per folder:
  - Listing, paginated: `/news`, `/news/page/N`. Tag listings are paginated the same way: `/news/tags/{tag}`, `/news/tags/{tag}/page/N`. Page size is `POSTS_PER_PAGE` at the top of `src/gen_blog.rs` (currently 5). Pages count from the newest post, so page URLs shift whenever a post is added.
  - `/news/archive`: every post title grouped by year (`template/blog_archive.hbs`).
  - `rss.xml` and `atom.xml`: all posts, not paginated.
- Sidebar: shows the newest `SIDEBAR_RECENT_POSTS` (20), plus the current post if it's older than those, plus an "All posts" link to the archive.
- Excerpts: a line containing only `<!-- more -->` (or `<!--more-->`), with blank lines around it, makes listings show only the part above it, followed by a "Read more" link. The split happens on the rendered HTML, so the marker must be its own block, not inside a paragraph or list. The post page and the feeds are unaffected.
- `PageContext.pagination` drives the pager in `blog_page.hbs` and the `<link rel=prev/next>` tags in `common_header.hbs`. Listing and archive pages use a synthetic `DocumentMeta` (url + section), so the top nav gets highlighted and `meta.section` works in templates.

## Performance

- A full build takes ~1 s in dev (`cargo run`), ~9.6 s before the fixes below. To find hot spots, timestamp each output line (`... | while read l; do echo "$(date +%s%N) $l"; done`), or wrap calls with an `Instant`-based accumulator. `perf` isn't installed.
- Handlebars serializes the whole render context to JSON on **every** render, and `PageContext` includes `globals`. Keep `GlobalMeta` small: bulky data (downloads, platforms, screenshots, ~180 KB of JSON) lives in `PageData` (`globals.page_data`, `#[serde(skip)]`), which is exposed as `page_data.*` only to `pages/*.hbs` (set in `Document::from_hbs`). Before this split, rendering took 6.9 of the 9.6 s.
- `[profile.dev.package."*"] opt-level = 2` in `Cargo.toml` optimizes dependencies (markdown, handlebars) in dev builds. That cut ~2.3 s to ~1 s, at the cost of a one-time ~70 s compile of dependencies.
- The ad hoc servers JSON is fetched from GitHub once per process, not on every watch-mode rebuild (it happens in `run()`, not `build()`).
- Markdown is parsed 2–3 times per document (summary extraction in `post_process.rs`, rendering, and the search index for docs). That's cheap (<1 s in debug before deps were optimized), so it wasn't worth merging.
- The output is deterministic (posts from the same day are sorted by slug; the search index is a `BTreeMap`), so to check that a refactor doesn't change output, build before/after and `diff -r` (ignore `lastBuildDate`/`<updated>` in the feeds). Build the "before" state in a `git worktree` with a separate `CARGO_TARGET_DIR`.
- A running `cargo run` dev server keeps its old binary but rebuilds on template changes, so after changing Rust code that templates depend on, it must be restarted. It also writes into the same `build/` dir, which can mess up before/after comparisons.

## Gotchas found so far

- Root-level files (`robots.txt`, `ads.txt`) live in `static/` and are copied to the build root in `src/main.rs`. Some root paths on www are served by nginx from `/srv/www/ppsspp.org/pub` instead of `build` (`/favicon.ico`, `/files/`, `/help/`, `/.well-known/`, …, and `/ads.txt` until that nginx rule is removed), so check the server config before assuming a file in `build/` is live.
- Ads: AdSense (`template/unit.hbs`, script loaded in `common_header.hbs`, skipped for Gold users via the `ppsspp-auth` localStorage cache). Google Analytics is the gtag snippet at the top of `common_header.hbs`.
- `feed.rs` hardcodes `https://www.ppsspp.org/{folder}` in feed links. Item links have a trailing slash, but the Atom `<id>`/RSS `<guid>` deliberately don't (that's how they were before; changing them makes readers re-show every post).

## URLs and SEO

- Canonical URLs end in a slash (every page is `foo/index.html`; nginx 301s `/foo` to `/foo/`). Internally `meta.url` stays slashless (`/news/foo`, `/index` for the front page); `util::canonical_path` converts.
- Every HTML page is written through `util::write_html`, which rewrites internal `href="/foo"` to `href="/foo/"` (`add_trailing_slashes`). So templates and Markdown can link either way. Files (extension containing a letter, e.g. `.mp4`, `.xml`; not `release-1.20.4`) and `/api/` are left alone. Links built in JS (`main.js`) and the search index URLs (`index.json`) are not rewritten.
- `PageContext.render()` fills `canonical_url` and `og_type` (`article` for dated `/news/` posts). `common_header.hbs` emits canonical, Open Graph and Twitter tags; `noIndex="true"` (used by notfound) emits `robots noindex` instead of canonical.
- `<title>` uses the `page_title` helper (registered in `main.rs` `build()`), which appends " – PPSSPP" unless the title already contains "PPSSPP".
- `<meta name="description">`: `description:` front matter, else the first top-level paragraphs of the Markdown joined until ~110 chars and cut to ~155 (`post_process::description_from_paragraphs`; skips text-less paragraphs like a lone image, stops before a paragraph ending in `:`), else `DEFAULT_DESCRIPTION` (meant for the front page only). News listings/tags/archive set their own in `gen_blog.rs`; docs categories without text in `_category_.md` list their contents. `.hbs` pages pass `description=` to `common_header`. Keep titles and descriptions unique per page.
- An `.hbs` page can override its canonical with `canonical_url="https://..."` on `common_header` (`gethomebrew_ios` points at `/gethomebrew/`; such pages go in `NOT_IN_SITEMAP`).
- `sitemap.xml` is written by `gen_sitemap.rs`: pages (minus `NOT_IN_SITEMAP` in `main.rs`), news listing/archive, posts, docs. `static/robots.txt` points to it.
- JSON-LD: `template/software_ld.hbs` (SoftwareApplication) on the front and download pages, WebSite + Organization in `pages/index.hbs`, BlogPosting on every post (`gen_blog::blog_posting_ld`, built with serde_json and passed as `PageContext.json_ld`, emitted in `common_header.hbs`; use `document::json_ld_script` for new ones so `</` is escaped). Docs breadcrumbs carry RDFa BreadcrumbList (`doc.hbs`).
- One `<h1>` per page. Listing pages show post titles as `h2.h1-style` (looks like an h1) under a `.visually-hidden` h1. The Markdown renderer drops a document's own `# Title` because the templates print the title (`doc.hbs`, `blog_post.hbs`, `page.hbs`).
- noindex (`noIndex="true"` on `common_header`): notfound, stats, login, changepassword, recoverpassword, thankyou, buildbotstatus.
- Images in Markdown content get `width`/`height` from the file at build time (`util::add_image_sizes`, unless the tag has width/height/class/style), against layout shift.
- Link previews: `og:image` is `static/img/share.png` (1280x640, same as the GitHub repo's social preview) with `twitter:card=summary_large_image`. A post or doc can set `image: /static/img/...` in its front matter. News posts without one use their first PNG/JPG/WebP/GIF (`first_share_image`); docs don't, since their images are mostly tall phone screenshots.
- News listing pages after the first (`/news/page/N`, `/news/tags/x/page/N`) are `noindex` (`PageContext.no_index`).
- Markdown links must be absolute (`/docs/...`), external, `mailto:` or `#anchor`. The build fails on relative links and on local links with `//` (`post_process::preprocess_markdown`), since pages are folders and relative links resolve under them. Link to own pages as `/docs/...`, not `https://www.ppsspp.org/docs/...`: only root-relative hrefs get the trailing slash added.
- Search Console traffic is seasonal: it peaks in summer and falls through autumn. Compare year over year before reading anything into a decline.

## Static assets and caching

- CSS/JS references carry a content hash: `/static/css/all.css?v={{globals.asset_v.all_css}}` (`AssetVersions` in `config.rs`, computed in `main.rs` from the *output* files with FNV-1a, `util::file_version`). nginx serves `?v=` requests as `immutable` for a year, and others for 1 h, so a new `<script>`/`<link>` to a file under `/static/` should get a `?v=` too (add a field to `AssetVersions`). Query strings rather than hashed file names because `deploy.sh` deletes old files while cached HTML may still reference them.
- `static/favicon.svg` (cleaned up from the 2020 Inkscape icon) and `static/manifest.webmanifest` are copied to the root with robots.txt/ads.txt. The manifest uses `display: browser` on purpose: no "install as app" prompt, the real app is native.
- `theme-color` follows the site theme (dark unless the visitor picked light), not `prefers-color-scheme`. Set in the inline script at the top of `common_header.hbs` and in `switchTheme()` in `main.js`.
- Screenshot gallery (`pages/media.hbs`, `static/css/gallery.css`): `data/gallery.json` lists the shots in display order (`file` = `ID_number_author.png/jpg`, `game_id`, `title`, `author` display name, e.g. `ASHU!` while files say `ASHU`). `util/gallery_images.py` makes `static/img/gallery/{full,thumb}/<name>.webp` (WebP q82 / 480x272 q80) from the ~1080p sources, which aren't in the repo (`~/ppsspp-screens/1080`, renamed and cropped there by its `process.py`). The build fails if a listed image is missing. The viewer is a `<dialog>` with an inline script; it adds a history entry so Android's back button closes it, and `/media/#<name>` opens a shot directly. The old slideshow images in `static/img/screenshots/` are unused but kept.
- `main.rs` top-of-file checklist tracks planned work ("Merge the two blogs", "Blog feed pagination", …).
- No headless browser in WSL, but Windows Chrome works headless from WSL (`chrome.exe --headless=new --screenshot=C:\\... --window-size=W,H --user-data-dir=<fresh dir> URL`) against `cargo run -- --port N` on localhost. Screenshots scrolled to an `#anchor` come out blank; take a tall one and crop.

## Server (nginx)

- Host `www@main` (ssh works; no sudo). Config: `/etc/nginx/sites-available/default`, nginx 1.18. `www.ppsspp.org` serves `/srv/www/ppsspp.org/prod/build`, `dev.ppsspp.org` serves `.../dev/build`. Each server block ends with a list of `location = /old { return 301 /new; }` redirects.
- nginx listens on :80 behind Cloudflare, so relative `return 301 /x` produces `Location: http://...` (an extra hop). Use `https://$host/...` in new redirects.
- To test a config change without root, run nginx with a throwaway config in a temp dir: `nginx -t -p $d -c $d/t.conf`, or even start it on a high port and `curl -H "Host: www.ppsspp.org"`. The "could not open error log" alert is harmless.
