# AGENTS.md

Notes for AI agents (and humans) working on the ppsspp.org site. Keep this updated as you learn things.

## Overview

- Static site for the PPSSPP PSP emulator, generated by a small custom Rust generator (`src/`), templated with Handlebars (`template/*.hbs`, pinned to `handlebars = "=6.4.0"`).
- Don't upgrade the `markdown` crate past what `Cargo.toml` says (there's a warning comment there).
- `cargo run` builds into `build/` and serves on `localhost:3000`, rebuilding on changes to `blog data docs news pages static template`. `cargo run -- --skip-serve` just builds.
- `build/` is not cleaned by `cargo run`, so stale output from removed/renamed posts stays around locally. `deploy.sh` does `rm -rf build` first, then rsyncs with `--delete-after` to `/srv/www/ppsspp.org/{dev,prod}`.
- The backend (`/api`, accounts, purchases) is closed source. Client-side login state lives in `static/script/account.js`.
- `drafts/` is never published.

## Content layout

- `docs/` → `gen_doctree.rs`, `pages/` (`.hbs` / `.md`) → `gen_pages.rs`.
- `news/` and `blog/` → both go through `gen_blog::generate_blog(config, folder, title, …)`, called twice from `src/main.rs` `build()`.
  - `news/`: ~71 posts from 2012 on, tagged `[releases]` or `[news]`. Titled "Release News". Its 3 newest posts feed `globals.latest_news` on the front page.
  - `blog/`: ~12 longer-form posts from 2023 on, tagged `[ppsspp]` or `[rendering-tricks]`. Titled "Development Blog".
  - Major releases usually get a pair: a detailed changelog in `news/` (slug `release-X.Y`) and a narrative post in `blog/` (slug `X-Y-release-announcement`), which cross-link.
- Post filenames are `YYYY-MM-DD-name.md`; the date comes from the filename. Front matter: `slug`, `title`, `authors`, `tags: [a, b]` (parsed in `document.rs`). Missing slug → falls back to the filename remainder with a warning.
- URL of a post: `/{folder}/{slug}`. Per-folder outputs: `index.html` (every post rendered in full, no pagination), `tags/{tag}/`, `rss.xml`, `atom.xml`.
- A post with no tags is omitted from the listing pages (listing filters by tag membership). All current posts have tags.

## Performance

- A full build takes ~1 s in dev (`cargo run`), ~9.6 s before the fixes below. To find hot spots, timestamp each output line (`... | while read l; do echo "$(date +%s%N) $l"; done`), or wrap calls with an `Instant`-based accumulator. `perf` isn't installed.
- Handlebars serializes the whole render context to JSON on **every** render, and `PageContext` includes `globals`. Keep `GlobalMeta` small: bulky data (downloads, platforms, screenshots, ~180 KB of JSON) lives in `PageData` (`globals.page_data`, `#[serde(skip)]`), which is exposed as `page_data.*` only to `pages/*.hbs` (set in `Document::from_hbs`). Before this split, rendering took 6.9 of the 9.6 s.
- `[profile.dev.package."*"] opt-level = 2` in `Cargo.toml` optimizes dependencies (markdown, handlebars) in dev builds. That cut ~2.3 s to ~1 s, at the cost of a one-time ~70 s compile of dependencies.
- The ad hoc servers JSON is fetched from GitHub once per process, not on every watch-mode rebuild (it happens in `run()`, not `build()`).
- Markdown is parsed 2–3 times per document (summary extraction in `post_process.rs`, rendering, and the search index for docs). That's cheap (<1 s in debug before deps were optimized), so it wasn't worth merging.
- The output is deterministic (posts from the same day are sorted by slug; the search index is a `BTreeMap`), so to check that a refactor doesn't change output, build before/after and `diff -r` (ignore `lastBuildDate`/`<updated>` in the feeds). Build the "before" state in a `git worktree` with a separate `CARGO_TARGET_DIR`.
- A running `cargo run` dev server keeps its old binary but rebuilds on template changes, so after changing Rust code that templates depend on, it must be restarted. It also writes into the same `build/` dir, which can mess up before/after comparisons.

## Gotchas found so far

- `template/common_header.hbs` advertises only `/blog/rss.xml` + `/blog/atom.xml` site-wide; the news feed isn't discoverable via `<link rel=alternate>`.
- `feed.rs` hardcodes `https://www.ppsspp.org/{folder}` and uses the channel description "PPSSPP Blog" for both feeds.
- `gen_sitemap.rs` collects entries but actually writing `sitemap.xml` is commented out.
- Known broken internal link: `blog/2023-04-30-progress-report.md` links `/news/2023-04-30-ppsspp-1.15` (the real slug is `release-1.15`).
- `main.rs` top-of-file checklist tracks planned work ("Merge the two blogs", "Blog feed pagination", …).
- No headless browser is installed locally, so visual checks have to be done by the user.
